# How the profile artwork works

GitHub strips JavaScript, `<style>` blocks and most HTML from a README, but an
SVG shown with `<img>` keeps its own CSS keyframes and SMIL animations. Every
moving part of this profile is therefore an SVG generated by
[`scripts/`](../scripts), using nothing but the Python standard library.

```bash
make build   # regenerate assets/
make check   # fail if assets/ is stale (CI runs this)
make test    # validity, accessibility and README link checks
```

## The stadium theme

The look follows the [stadium portfolio](https://stadium-portfolio.vercel.app):
projects are players, the README is a matchday programme.

| Asset | Module | What moves |
| :-- | :-- | :-- |
| `stadium-hero.svg` | `hero.py` | Floodlights switch on in turn, the surname draws itself in, the role line cycles, players chase the ball, the ticker scrolls |
| `sections/*.svg` | `banners.py` | Heading rises in, the lime bar sweeps across |
| `scoreboard.svg` | `scoreboard.py` | Odometer digits roll up to each stat |
| `ticker.svg` | `ticker.py` | Endless honours marquee |
| `captain.svg` | `captain.py` | Stat tiles and the four stages rise in turn, border spark |
| `pitch.svg` | `pitch.py` | The ball is passed keeper → striker → goal; each player lights up on the touch |
| `cards/*.svg` | `cards.py` | Content rises in, a spark of light runs around the border |
| `bench.svg` | `bench.py` | Tiles rise in one after another |
| `honours.svg` | `honours.py` | A shine sweeps across the trophy cabinet |
| `portfolio.svg`, `fulltime.svg` | `cta.py` | Pulsing button ring, orbiting floodlight, a Mexican wave in the crowd |

## Rules every asset follows

- **Resting state is the final state.** Animations only describe how an
  element arrives, so a paused or reduced-motion render still reads correctly.
- **`prefers-reduced-motion` is honoured** in every file.
- **Self-contained.** No web fonts, external images or scripts: GitHub's image
  proxy would block them. Fonts fall back to system faces.
- **Deterministic.** Randomness is seeded, so `--check` can spot stale output.
- **Accessible.** Each SVG has `role="img"`, an `aria-label` and a `<title>`;
  each `<img>` in the README has alt text.

## Changing content

All copy lives in [`scripts/data.py`](../scripts/data.py) and mirrors the
portfolio's data. Edit it, run `make build`, and commit the regenerated SVGs
together with the change. The tests check that card copy still fits and that
the commit total on the scoreboard matches the squad.
